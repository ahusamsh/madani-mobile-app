# النشر والتراجع وعمليات التشغيل

## 1. ما هو منشور، ومن أين؟

- مصدر الإنتاج في GitHub: `main` من `ahusamsh/madani-mobile-app`.
- GitHub Pages مضبوط على `main` والمسار الجذري `/`، والبناء الحالي يعمل بطريقة Pages القديمة (`legacy`).
- الرابط المعتمد للمستخدمين: https://madani-mobile-reader.vercel.app/.
- Vercel `madani-mobile-reader`: عنوان مستقل يحتوي في النشر الحالي على نسخة مدخلة من `index.html` وقواعد Rewrite لمسارات أخرى إلى مصدر الاستضافة القديم؛ **ليس Vercel مشروعًا متصلًا تلقائيًا بفرع GitHub لهذا المستودع**.
- رابط معاينة V3 منفصل عن نطاق الإنتاج: https://madani-mobile-reader-qtdpopqxv-ahusamshs-projects.vercel.app/vision/camera-v2.html?engine=v3.
- لا تعرض نطاق المشروع الآخر في الروابط الموجهة للمستخدم، ولا تغيّر الاستضافة أو الدومين دون تفويض.

## 2. منع تسرب V3 إلى الإنتاج قبل الاعتماد

`feature/vision-v3-accuracy` وPR #7 يحتفظان بكود V3 والبيانات التجريبية. يظل V2 افتراضيًا في `main`. النتائج الآلية الإيجابية وحدها لا تكفي لنشر V3 الافتراضي؛ يلزم اختبار واقعي لصفحات 13 و25 و28 و47 وقلم من اليمين، وحل حالات التراجع أو تسجيل قبول واعٍ للمخاطر.

## 3. القائمة قبل الدمج

1. `git status --short` فارغ أو يحتوي فقط على تغييرات معروفة على فرع العمل، دون أسرار أو مخرجات اختبار عارضة.
2. `node scripts/qa.cjs` بلا ملفات MP3 مفقودة أو مراجع غير صالحة.
3. اختبارات Node للمحرك السابق والجديد ناجحة على نسخة العمل نفسها.
4. تنتهي مقارنة V2/V3 على العينات نفسها وتوضح `correct`, `wrong`, `silent`, `pageWrong`, P50/P95.
5. وثّق اختبار الهاتف (إصبع، قلم، إضاءة، صفحات متشابهة، عدم وجود مؤشر).
6. حزم Offline اكتملت والتحقق من SHA-256 نجح بعد قطع الشبكة ثم إعادة فتح المتصفح والكتاب.
7. راجع تغير `data/audio-library.json`, `data/offline-packs.json`, `sw.js` وأرقام النسخة والخدمة.
8. توجد خطة رجوع إلى إصدار `main` السابق في GitHub، وV2 موجود ويعمل.

## 4. نشر تعديل آمن

```bash
git switch -c feature/my-change
# التعديل والاختبار
git diff --check
git add <reviewed-files>
git commit -m "fix: explain effect"
git push -u origin feature/my-change
```

افتح Pull Request ثم أجر المراجعة والاختبارات. عند اعتماد الدمج إلى `main` ينتج بناء GitHub Pages؛ تابع GitHub Actions/Pages حتى يكتمل. **لا تدمج PR #7 لمجرد أن Vercel Preview يعمل**.

## 5. تحقق ما بعد النشر

استخدم رابط المستخدم الرسمي (وليس الرابط الداخلي)، وراجع HTTP 200 والـContent-Type للصفحة الرئيسية و`vision/camera-v2.html` و`vision/data/ref-index.bin` و`data/audio-library.json` و`data/offline-packs.json` و`sw.js` وعينة من الصور والصوت. جرّب الكاميرا وارتباط صوت معروف، ثم حالة صامتة بدون مؤشر.

انتبه: صفحة `/` قديمة أحيانًا لأن Vercel يملك نسخة `index.html` منشورة **بشكل منفصل** عن GitHub Pages، بينما بقية الملفات تمر عبر Rewrite. إذا تغيرت الصفحة الرئيسية على GitHub فلا تتوقع أن تتحدث على Vercel تلقائيًا؛ يجب إعادة نشر ملف `index.html` على مشروع Vercel نفسه عند اعتماد واجهة جديدة، مع اختبار الرابط. لا تنشر رابطًا غير مجرّب.

## 6. Offline وService Worker

- `sw.js` يخزن shell وملفات PWA ويحتفظ بحزم الصوت والكتاب وفق معرفات الإصدارات.
- عند تعديل JS الخاص بالمحرك، حدّث shell/version واختبر التثبيت الأول والتحديث من نسخة قديمة.
- بعد إضافة أصوات أو تعديل خرائط الصفحات، **أعد توليد** `data/audio-coverage.json` و`data/offline-packs.json`، وراجع أن ملفات الحزم موجودة وبصماتها مطابقة.
- ملف Manifest يحمل SHA-256 للبايتات المنشورة، ولذلك يسبب CRLF في Windows فسادًا ظاهريًا في الاختبارات إذا خالف LF الأصلي. فرع V3 أضاف `.gitattributes` لتثبيت LF؛ تحقّق من خصائص المستودع على فرعك.
- لإثبات Offline: نزّل `camera-ar` و`book-ar`، تحقّق من كل الملفات، اقفل التطبيق، افصل الإنترنت، ثم افتح الكاميرا والكتاب وشغّل مقطعًا موجودًا. لا يكفي مجرد ظهور علامة Service Worker.
- بعد تحديث الصوتيات قد يحتاج المستخدم إلى تحديث حزمة الكاميرا العربية **من داخل واجهة التنزيل**؛ لا توجّه المستخدم إلى مسح كل التخزين دون ضرورة.

## 7. الاستجابة للأعطال

| العطل | التشخيص المبدئي |
|---|---|
| 404 على رابط Vercel | افحص Rewrite والملف المصدر والنشر؛ لا تفترض أن حالة READY تعني سلامة جميع المسارات |
| الصفحة الرئيسية قديمة | يوجد `index.html` ثابت داخل نشر Vercel؛ يحتاج تحديث منفصل بعد تعديل main |
| «غير مؤكد» مع وجود قلم | راجع فهرس الصفحة ومطابقة المعالم ونقطة الطرف والمستطيلات؛ افحص V2 مقابل V3 |
| سماع حرف مجاور | عطل عالي الخطورة تعليميا؛ أوقف المسار المتأثر وأصلح اختيار الحبر، لا تخفّض عتبة الثقة عشوائيًا |
| كلمة صحيحة بلا صوت | راجع `segments[zoneId]`, مسار `clip`, تغطية الصفحة، واستجابة الملف 200 |
| اكتمال Offline يفشل | طابق Manifest مع البايتات الفعلية، حجم الملفات، وCRLF/LF ونسخة الحزمة المخزنة |
| الصفحة 47 تُكتشف 49 | راجع V3 `page-discriminate` أو ارفض الصفحة غير المؤكدة |

## 8. خطة الرجوع عند فشل نسخة جديدة

1. لا تمسح بيانات المستخدم المحلية أو التسجيلات الأصلية.
2. أوقف تفعيل المسار الجديد واجعل `?engine=v2` أو رابط V2 هو الافتراضي عند الحاجة.
3. أرجع `main` عن Commit/PR المسبب باستخدام `git revert <merge-commit>` بعد مراجعته؛ لا تستخدم `git push --force` على الفرع المشترك.
4. تابع اكتمال بناء GitHub Pages، ثم تحقق من رابط Vercel الرسمي والمسارات الداخلية فعليًا.
5. إذا كانت الصفحة الرئيسية في Vercel معدلة، أعد نشر نسخة الصفحة الرئيسية المستقرة أيضًا.
6. احتفظ بتقارير الخطأ وصورة أو تسجيل مثال مع مراعاة الخصوصية، وضعها في Issue للمتابعة.

## 9. صلاحيات التعاون

المستودع في وضع القراءة العامة حاليًا، لكن صلاحية Push تحتاج دعوة. أُرسلت دعوة حساب `msdxlab` (مسعود محمد) بصلاحية **Write**، ويجب أن يقبلها قبل الاعتماد عليها. اعمل بفرع مستقل وPull Request؛ لا تُخزّن كلمات مرور أو رموز دخول في المستودع. إدارة صلاحيات GitHub والنشر والصوتيات الأصلية بيد مالك المشروع.

## 10. سياسة التكاليف والأجهزة

لا تُضف استضافة أو اشتراكًا مدفوعًا دون موافقة مسبقة. لا تستخدم جهاز التدريب لتنفيذ Vision/Audio. استخدم حاسوب تطوير عادي لاختبارات بناء الفهرس أو OCR/ASR المحلي، مع مراعاة أن PWA يعمل على الهاتف نفسه دون اتصال بخادم AI.
