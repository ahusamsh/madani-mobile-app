# دليل استلام مشروع القاعدة المدنية التفاعلية

> تحديث حالة المشروع: 5 نوفمبر 2026. هذه هي نقطة الدخول للمطورين، بما في ذلك مسعود. لا تُفهم نتائج المحاكاة على أنها اعتماد ميداني.

## المستودع والإصدارات

- المستودع الأساسي: https://github.com/ahusamsh/madani-mobile-app
- الفرع `main`: النسخة المنشورة المستقرة، محرك الكاميرا V2 افتراضيًا.
- الفرع `feature/vision-v3-accuracy`: تطويرات Claude Vision V3، **لم تُدمج في main**، وطلبها https://github.com/ahusamsh/madani-mobile-app/pull/7.
- رابط المستخدم المعتمد (لا يتضمن نطاق المشروع الآخر): https://madani-mobile-reader.vercel.app/
- تجربة V2: https://madani-mobile-reader.vercel.app/vision/camera-v2.html
- معاينة V3 المنفصلة، تمت تجربتها في Chrome: https://madani-mobile-reader-qtdpopqxv-ahusamshs-projects.vercel.app/vision/camera-v2.html?engine=v3
- إصدارات V1 وV2 وV3 لا تتطلب خادم استدلال؛ معالجة الكاميرا على جهاز القارئ.

## ابدأ بهذه الخطوات

1. اقبل دعوة GitHub إن كنت متعاونًا جديدًا، ثم استنسخ المشروع باستخدام حساب GitHub المصرح.
2. ابدأ من الفرع المستقر `main`، وافتح التطبيق عبر خادم HTTP محلي، لا من `file://`.
3. اقرأ [المعمارية وقاموس البيانات](ARCHITECTURE.md) لفهم فصل الصفحة، والمؤشر، والنطق.
4. اتبع [خطوات التطوير والاختبارات](DEVELOPMENT_TESTING.md) لتجهيز البيئة وتشغيل الفحوص.
5. اقرأ [دليل V3 والمشكلات الموثقة](VISION_V3_HANDOFF.md) قبل تعديل المحرك.
6. اقرأ [دليل الصوتيات ومراجعتها](AUDIO_LIBRARY.md) قبل إضافة أي ربط صوتي.
7. التزم بـ[إجراءات الدمج والنشر والتراجع](RELEASE_RUNBOOK.md).

## قواعد أساسية

- لا تستخدم جهاز التدريب/GPU المرتبط بمشاريع أخرى، ولا خوادم OCR أو APIs مدفوعة في تشغيل هذا المنتج.
- لا تسمح بنطق دون وجود طرف إصبع أو قلم موثوق، ولا تشغّل تسجيلًا عشوائيًا عند غياب الرابط الصحيح.
- لمس أي حرف داخل **كلمة** ينطق الكلمة كاملة؛ الحرف التعليمي المستقل ينطق وفق التسجيل التعليمي.
- لا تحذف V2 عند تطوير V3، ولا تنقل V3 للإنتاج دون مقارنة وتحقق بكاميرا هاتف فعلي.
- أصل البيانات: تسجيلات القاعدة الأصلية، والكتاب الأصلي؛ لا تستبدلها بصوت TTS اصطناعي.
- لا تدخل رموز الوصول، كلمات المرور، بيانات الحسابات، ملفات البيئة السرية أو تعريفات الأجهزة ضمن GitHub.
- عند إضافة بيانات/صور/أصوات، أعد توليد فهرس الرؤية وحزمة Offline ثم تحقق من بصمات الملفات.

## طريقة العمل بين المطورين

فرع لكل مهمة، Commit صغير مع اختبار ومخرجات مقارنة قابلة للتكرار، Pull Request إلى `main` مع مراجعة. لا تعتمد على وعود أو تقارير Claude وحدها؛ ضع الأدلة والاختبارات ضمن المستودع. استعمل حساب `msdxlab` بعد قبول الدعوة وصلاحية Write. صلاحية Write لا تعني أن ترقية V3 للإنتاج مُعتمدة تلقائيًا.

## أين أجد الحقائق؟

- `data/audio-library.json`: مصدر ربط النص/المناطق بالتسجيل الأصلي.
- `data/audio-coverage.json`: أرقام التغطية، وتُحدّث بالأمر `node scripts/audio-coverage.cjs`.
- `vision/data/ref-index.bin`: فهرس الرؤية الثنائي للصفحات.
- `data/offline-packs.json`: قائمة الحزم وبصمات SHA-256.
- `vision/bench/results-v2-vs-v3.json` **على فرع V3**: مقارنة محاكاة V2/V3.
- `vision/bench/results-v3-offline.json` **على فرع V3**: نتائج اختبار Offline المحاكى.
- `README.md`: خلفية المشروع وبعض السجلات التاريخية؛ قد تحتوي فقرات قديمة، فاجعل هذا الدليل وملفات JSON المصدر الأحدث.

## ملحوظات لا تُغفل في التسليم

تحديث GitHub لا يساوي تحديث رابط Vercel المستقل في جميع الحالات: الصفحة الرئيسية في Vercel لها ملف منشور مستقل، بينما تعاد كتابة كثير من المسارات الداخلية إلى الموقع المنشور. تجب مراجعة كل مسار فعليًا بعد أي نشر. رابط معاينة V3 عبارة عن نشر مستقل ولم يصبح النسخة الرسمية.

لمنع التشتت: **اقرأ الملفات الخمسة المشار إليها أعلاه أولًا، ثم ابدأ من اختبارات V2، وبعدها اختبارات V3**.
